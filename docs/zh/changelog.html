更新日志

v0.1.2 - 2026 年 11 月 26 日

  • 新增通知投递的出站代理支持：全局 alerts.general.proxy（url + no_proxy）作用于所有通知渠道和监控探活，每个服务商档案也可设置自己的 proxy 覆盖项——留空跟随全局代理，direct 强制直连，或填该档案自己的代理地址（http://、https://、socks5:// 或 socks5h://，可带凭据）
  • Frigate 服务器本身永不走代理：其主机始终位于绕过名单中，no_proxy 名单同样覆盖 SMTP 投递，发往 Frigate 的请求继续遵循 Frigate HTTP 约定
  • 不静默回退：代理不可达时投递直接失败，错误信息会点名该代理；代理凭据在日志、校验错误和 Web UI 保存差异预览中均会打码

v0.1.1 - 2026 年 11 月 26 日

  • 为定时 GenAI 总结新增聊天摘要：Frigate 的 chat 接口把窗口内的事件编排成一份按时间顺序排列的摘要，每个定时计划可携带自定义提示词，并有一套回退阶梯（chat -> 窗口内有被标记事项时改用 summarize -> 逐事件列表 -> “无活动”一行）确保摘要一定能送达
  • 修复 chat 请求绕过共享 Frigate HTTP 约定的问题：现在改走 util.HTTPPostFrigate，带登录会话并支持 ignoressl，因此在 Frigate 开启鉴权或 Frigate 使用自签名 HTTPS 证书时，摘要也能正常工作
  • 修复一次运行缓慢的总结会把相邻定时计划吞掉一整天的问题：到期的计划现在在派发时即标记为已触发，且每个计划在各自的 goroutine 中运行
  • 修复 Frigate 那句现成的 “maximum tool call iterations” 回复被当作摘要送达的问题：带 finish_reason=length 的 chat 响应现在按失败处理并走回退
  • 修复通知发送并发时通知状态计数器的竞态（计数器现由互斥锁保护）

v0.1.0 - 2026 年 11 月 25 日

  • 本 fork 自有版本线上的首个版本：Frigate Notify Plus 不再跟随上游 frigate-notify 的版本号——v0.5.4-webui.* 预发布系列止于 v0.5.4-webui.15，应用现在自报版本为 v0.1.0
  • 重新设计 Web UI 控制台：侧边栏外壳，常驻状态摘要、基于 hash 的深层链接（#/status、#/config/<section> 等）、状态仪表盘、带改动计数和保存差异预览的悬浮保存坞，以及标签页式模板编辑器
  • 新的默认 Web UI 配色：更明亮的蓝色设计体系取代了之前的浅色主题；深色、护眼绿和 Argon 主题仍然可用
  • Web UI 现已双语：侧边栏中的 中文 / English 切换器可就地切换全部界面文字（选择保存在浏览器中，默认中文）
  • 修复状态页的通知磁贴在真实通知状态加载完成前短暂显示为“开”的问题；现在它会显示加载状态，直到状态已知
  • 修复 GenAI 与威胁优先级配置卡片的“已修改”徽标亮错区块的问题，并让这些卡片的恢复默认按钮只作用于各自的设置
  • 精简双语 README（347 → 90 行）并加入 Web UI 截图
  • 项目更名为 Frigate Notify Plus（github.com/izerok/frigate-notify-plus，二进制/镜像名 frigate-notify-plus）；Web UI 控制台、GenAI 通知、按相机冷却、路由规则、威胁优先级、按相机静音、Bark 渠道、GenAI 升级、每小时通知上限和定时 GenAI 总结都是 fork 功能——见 README
  • 新增先发送快照、再通过 Telegram 把同一条消息就地替换为事件视频片段的能力（send_clip_after_snapshot），并可通过 clip_max_size 配置上传大小上限
  • 新增在上传前用 ffmpeg 把 Telegram 视频片段重新编码为更小视频的选项（clip_transcode），可选择通过 VAAPI 使用 GPU。Docker 镜像现已基于 Alpine 并包含 ffmpeg
  • Frigate 0.18 支持：威胁等级现在渲染为 "Normal"、"Suspicious" 或 "Critical"，与 Frigate 的 0-2 量表一致（此前为 "Minor"/"Moderate"/"High"）
  • 新增 .Extra.GenAIObservations 模板变量（Frigate 0.18+），并将其作为时间线附加到 Telegram GenAI 更新中；默认 webhook 载荷中也包含它
  • 当 GenAI 活动总结请求被拒绝时，带上 Frigate 的错误信息
  • 修复 GenAI 活动总结带着 Frigate 的 “No activity/concerns were found” 占位文字发送的问题；现在只有当该时段内有审查被 GenAI 标记时才请求总结
  • 修复初始通知已被丢弃的审查仍会发送 GenAI 更新通知的问题（例如关闭了 notify_detections 的仅检测审查，或被区域/标签/相机过滤掉的审查）
  • 修复当 GenAI 更新在初始通知仍在发送过程中到达时，Telegram 通知重复、且 GenAI 说明文字被片段替换撤销的问题；更新现在会等待该通知发送完成后再编辑它
  • 在 reviews 模式下，被跟踪对象现在每个区域只通知一次，即使它出现在多个 Frigate 审查中，直到它有 1 小时没有在新区域上通知过（此前每个新审查都可能再次通知）
  • 在 reviews 模式下，已经通知过的对象（按其区域，或在 notify_once 下整体）不再阻止同一审查中的新对象通知；通知会为新对象发送
  • 在 reviews 模式下，被过滤丢弃的对象（例如静默时段或 min_score）在通过过滤后仍可通知；此前它的区域已被计为已通知
