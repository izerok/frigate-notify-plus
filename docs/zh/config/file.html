文档/配置/配置文件

配置文件

以下部分详细介绍可通过 config.yml 文件设置的选项。每个部分都提供了配置片段，不过建议从一份空白的完整示例配置开始。

配置也可以通过环境变量提供。Frigate-notify 会加载带 FN_ 前缀的环境变量。环境变量与下面的配置文件遵循相同的结构，层级之间用两个下划线（__）分隔。例如，设置 Frigate 服务器地址为 FN_FRIGATE__SERVER，启用 Discord 通知为 FN_ALERTS__DISCORD__ENABLED。如果配置了多个通知档案，它们用从零开始的索引指定——例如：FN_ALERTS__DISCORD__0__ENABLED、FN_ALERTS__DISCORD__1__ENABLED 等。下文中，环境变量键会与配置文件键一同列出。

配置按以下顺序加载并合并：配置文件 > 环境变量 > Docker secrets。这样大部分配置可以通过配置文件提供，而秘密信息可以通过环境变量或 docker secrets 提供。

配置文件位置

配置文件按以下顺序解析：

  1. -c 参数（例如 -c /app/config.yml）
  2. FN_CONFIGFILE 环境变量
  3. 设置了数据目录时为 $DATA_DIR/config.yml（-d / --data-dir 参数或 FN_DATA_DIR 环境变量）
  4. 工作目录下的 ./config.yml（旧版默认）

Docker 镜像设置了 FN_DATA_DIR=/data，因此在容器中配置文件默认为 /data/config.yml。把主机目录挂载到 /data 即可持久化它：数据目录还存放 logs/frigate-notify.log（10 MB 轮转，保留 5 个备份）、mute.json（按相机静音）、templates/（在 Web UI 中编辑的消息模板，每个模板一个文件），以及 history.jsonl（最近通知历史：JSON Lines 格式，每行一条，内存中保留最新 100 条，文件超过 1000 行时压缩整理）。删除容器不会删除这些数据。保存时写出的配置备份（config.yml-<timestamp>.bak）同样落在数据目录中。

App

  • mode（可选 - 默认：reviews）
    • 环境变量：FN_APP__MODE
    • 指定通知基于 Frigate 的事件还是审查
    • events 会对 Frigate 检测到的每个对象都发通知
    • reviews 只对 Frigate 警报发通知（需要 Frigate 0.14+）
      • 在 reviews 模式下，打开 alerts 配置部分下的 notify_detections 可同时对检测发通知
      • 另见 Alerts 与 Detections
  • API
    • enabled（可选 - 默认：false）
      • 环境变量：FN_APP__API__ENABLED
      • 设为 true 启用 Frigate-Notify-Plus 的 REST API 服务器
    • port（可选 - 默认：8000）
      • 环境变量：FN_APP__API__PORT
      • 更改 API 服务器的默认端口
Config File Snippet
app:
  mode: events
  api:
    enabled: true
    port: 8000

Frigate

服务器

  • server（必填）
    • 环境变量：FN_FRIGATE__SERVER
    • Frigate NVR 的 IP、主机名或 URL
    • 如果指定的是 IP 或主机名，应用会自动在前面加上 http://
    • 如果 Frigate 不在反向代理之后，必要时在后面附上端口号
  • ignoressl（可选 - 默认：false）
    • 环境变量：FN_FRIGATE__IGNORESSL
    • 设为 true 可为 server 允许自签名证书
  • public_url（可选）
    • 环境变量：FN_FRIGATE__PUBLIC_URL
    • 如果 Frigate 可通过外部公共 URL 访问，应设置此项
    • 该值用于通知中的链接
    • 格式应为完整 URL（例如：https://nvr.your.public.domain.tld）
  • username（可选）
    • 环境变量：FN_FRIGATE__USERNAME
    • 使用 8971 端口的带鉴权 UI 时，用于登录的 Frigate 用户名
    • 如果配置了用户名，必须同时配置密码
    • 建议为 frigate-notify-plus 创建一个独立用户，并赋予 viewer 角色
  • password（可选）
    • 环境变量：FN_FRIGATE__PASSWORD
    • 使用 8971 端口的带鉴权 UI 时，用于登录的 Frigate 密码
    • 如果配置了密码，必须同时配置用户名
  • headers（可选）
    • 环境变量：FN_FRIGATE__HEADERS
    • 向 Frigate 发送额外的 HTTP 请求头
    • 适用于鉴权等场景
    • 请求头格式：Header: Value
    • 示例：Authorization: Basic abcd1234
  • startup_check（可选）
    • 启动时，frigate-notify-plus 会尝试连接配置的 Frigate NVR 以验证连通性
    • 这些选项可自定义最大尝试次数和重试间隔
    • attempts（可选 - 默认：5）
      • 环境变量：FN_FRIGATE__STARTUP_CHECK__ATTEMPTS
      • 连接 Frigate 服务器的最大尝试次数
    • interval（可选 - 默认：30）
      • 环境变量：FN_FRIGATE__STARTUP_CHECK__INTERVAL
      • 重试之间的间隔，单位为秒
Config File Snippet
frigate:
  server: nvr.your.domain.tld
  ignoressl: true
  public_url: https://nvr.your.public.domain.tld
  headers:
    - Authorization: Basic abcd1234
  startup_check:
    attempts: 5
    interval: 30

WebAPI

Note

只能配置一种监控方式，webapi 或 mqtt 二选一。另一种必须设为 enabled: false。

  • enabled（可选 - 默认：false）
    • 环境变量：FN_FRIGATE__WEBAPI__ENABLED
    • 设为 true 时，Frigate 事件通过轮询 Web API 收集
  • interval（可选 - 默认：30）
    • 环境变量：FN_FRIGATE__WEBAPI__INTERVAL
    • 检查 Frigate Web API 是否有新事件的频率，单位为秒
Config File Snippet
frigate:
  webapi:
    enabled: true
    interval: 60

MQTT

Note

只能配置一种监控方式，webapi 或 mqtt 二选一。另一种必须设为 enabled: false。

  • enabled（可选 - 默认：false）
    • 环境变量：FN_FRIGATE__MQTT__ENABLED
    • 设为 true 时，Frigate 事件通过 MQTT broker 收集
    • 注意：这必须是 Frigate 发送事件所用的同一个 MQTT broker
  • server（必填）
    • 环境变量：FN_FRIGATE__MQTT__SERVER
    • MQTT 服务器的 IP 或主机名
    • 如果启用了 MQTT 监控，此字段必填
  • port（可选 - 默认：1883）
    • 环境变量：FN_FRIGATE__MQTT__PORT
    • MQTT 服务端口
  • clientid（可选 - 默认：frigate-notify-plus）
    • 环境变量：FN_FRIGATE__MQTT__CLIENTID
    • 本应用连接 MQTT 时使用的客户端 ID
    • 注意：该值必须唯一，不能与其他 MQTT 客户端共用
  • username（可选）
    • 环境变量：FN_FRIGATE__MQTT__USERNAME
    • MQTT 用户名
    • 如果用户名和密码都未设置，则禁用鉴权
  • password（可选）
    • 环境变量：FN_FRIGATE__MQTT__PASSWORD
    • MQTT 密码
    • 如果设置了 username，则此项必填
  • topic_prefix（可选 - 默认：frigate）
    • 环境变量：FN_FRIGATE__MQTT__TOPIC_PREFIX
    • 可选地更改 MQTT 主题前缀
    • 应与 Frigate 使用的主题前缀一致
Config File Snippet
frigate:
  mqtt: 
    enabled: true
    server: mqtt.your.domain.tld
    port: 1883
    clientid: frigate-notify-plus
    username: mqtt-user
    password: mqtt-pass
    topic_prefix: frigate

相机

  • exclude（可选）
    • 环境变量：FN_FRIGATE__CAMERAS__EXCLUDE
    • 如有需要，提供一份要忽略的相机列表
    • 这些相机上的任何 Frigate 事件都不会产生通知
    • 如果留空，此功能禁用，所有相机都会产生通知
    • 如果通过环境变量配置，用分号分隔相机名称
Config File Snippet
frigate:
  cameras:
    exclude:
      - test_cam_01
      - test_cam_02

通知

Note

可以启用任意组合的通知方式，不过你大概至少想启用一种！😅

所有通知渠道（Discord、Gotify 等）也都支持可选的过滤条件，并可为每个渠道配置多个档案。更多信息见通知档案与过滤。

通用

  • cooldown（可选 - 默认：0）
    • 环境变量：FN_ALERTS__GENERAL__COOLDOWN
    • 任意相机两次通知之间的最短秒数。必须为非负整数；0 表示禁用全局冷却。
  • camera_cooldown（可选 - 默认：{}）
    • 环境变量示例：FN_ALERTS__GENERAL__CAMERA_COOLDOWN__DOORBELL=30
    • 把 Frigate 相机名称映射到冷却秒数（非负整数）
    • 未列出的相机以及值为 0 的相机没有相机专属冷却
    • 全局冷却和相机冷却都必须经过之后，才会发送下一条通知
  • title（可选 - 默认：Frigate Alert）
    • 环境变量：FN_ALERTS__GENERAL__TITLE
    • 生成的通知消息的标题（电子邮件主题等）
    • 标题值可以使用模板变量
  • timeformat（可选 - 默认：2006-01-02 15:04:05 -0700 MST）
    • 环境变量：FN_ALERTS__GENERAL__TIMEFORMAT
    • 可选地为通知设置自定义日期/时间格式
    • 它使用 Golang 的参考时间进行格式化
    • 帮助见这篇指南
    • 下面的示例使用 RFC1123 格式
  • nosnap（可选 - 默认：allow）
    • 环境变量：FN_ALERTS__GENERAL__NOSNAP
    • 指定如何处理没有快照图片的事件
    • 默认情况下，这些事件会被发送，通知消息会说 “No snapshot available”
    • 设为 drop 可静默丢弃这些事件，不发送通知
  • snap_bbox（可选 - 默认：false）
    • 环境变量：FN_ALERTS__GENERAL__SNAP_BBOX
    • 从 Frigate 获取快照时，在快照上包含对象边框
    • 注意：在 Frigate 0.17 及更早版本上，这只在事件进行中时应用。Frigate 0.18+ 按请求渲染快照，因此对已完成的事件同样应用；当此项为 false 时，Frigate 会回退到相机自身的 snapshots 配置
  • snap_timestamp（可选 - 默认：false）
    • 环境变量：FN_ALERTS__GENERAL__SNAP_TIMESTAMP
    • 从 Frigate 获取快照时，在快照上包含时间戳
    • 注意：Frigate 版本行为与 snap_bbox 相同
  • snap_crop（可选 - 默认：false）
    • 环境变量：FN_ALERTS__GENERAL__SNAP_CROP
    • 从 Frigate 获取快照时裁剪快照
    • 注意：Frigate 版本行为与 snap_bbox 相同
  • snap_hires（可选 - 默认：false）
    • 环境变量：FN_ALERTS__GENERAL__SNAP_HIRES
    • 默认情况下，快照从 Frigate 的检测码流收集，分辨率可能较低
    • 设为 true 可从相机录像码流收集快照
    • 注意：启用后，上面 snap_bbox、snap_timestamp 和 snap_crop 的设置不起作用
    • 注意：用这种方式生成的快照基于 Frigate 提供的事件开始时间
      • 这意味着收集到的快照可能与 Frigate 为该事件选择的快照不同
      • 这也意味着，根据检测时机，这张快照可能不包含被检测到的对象
      • 如果确保快照始终包含被检测对象是优先事项，建议保持此选项禁用
  • max_snap_retry（可选 - 默认：10）
    • 环境变量：FN_ALERTS__GENERAL__MAX_SNAP_RETRY
    • 等待快照可用时的最大重试次数
    • 每 2 秒重试一次
    • 默认为 10，即最多等待 20 秒等快照
    • 注意：如果从 Frigate 收到的事件包含 has_snapshot: false，此项不适用
  • notify_once（可选 - 默认：false）
    • 环境变量：FN_ALERTS__GENERAL__NOTIFY_ONCE
    • 默认情况下，每个 Frigate 事件可能随着对象在区域间移动等情况产生多条通知
    • 设为 true 可让每个事件只通知一次
  • notify_detections（可选 - 默认：false）
    • 环境变量：FN_ALERTS__GENERAL__NOTIFY_DETECTIONS
    • 仅当应用 mode 为 reviews 时使用
    • 默认情况下，通知只在 Frigate 警报时发送
    • 设为 true 可同时对检测发通知
  • recheck_delay（可选 - 默认：0）
    • 环境变量：FN_ALERTS__GENERAL__RECHECK_DELAY
    • 可选地在发送通知前从 Frigate 重新检查事件详情
    • 延迟时间，单位为秒
    • 设为 0 时，事件在从 Frigate 收到后立即发送
    • 如果需要等待第三方应用设置 sub_labels，这个设置会很有用
  • audio_only（可选 - 默认：allow）
    • 环境变量：FN_ALERTS__GENERAL__AUDIO_ONLY
    • 指定如何处理只包含音频检测的事件
    • 默认情况下，这些事件会产生通知
    • 设为 drop 可静默丢弃这些事件，不发送通知
  • max_notifications_per_hour（可选 - 默认：0）
    • 环境变量：FN_ALERTS__GENERAL__MAX_NOTIFICATIONS_PER_HOUR
    • 每个滚动小时内跨所有渠道下发的最大通知数
    • 设为 0 表示不限制
    • 只有实际下发的通知才计数——被过滤、被静音和被冷却挡下的通知不计数，测试通知豁免
    • GenAI 更新和升级通知会计入上限
  • genai（可选）
    • Frigate 的 GenAI 功能支持设置
    • 当 Frigate 配置了 GenAI 时，它会为审查事件生成 AI 描述，包括标题、场景总结、威胁等级和对象描述
    • 这些内容在可用时会自动包含在通知中
    • enabled（可选 - 默认：true）
      • 环境变量：FN_ALERTS__GENERAL__GENAI__ENABLED
      • 设为 false 可把 GenAI 数据排除在通知之外
      • 启用时，当 Frigate 提供 GenAI 数据时，通知会包含 AI 生成的标题、总结、威胁等级和其他 GenAI 元数据
    • update_notif（可选 - 默认：true）
      • 环境变量：FN_ALERTS__GENERAL__GENAI__UPDATE_NOTIF
      • GenAI 数据可能在初始通知已经发送之后才到达
      • 设为 true 可在 GenAI 数据可用时发送一条更新通知
      • 更新只针对产生过初始通知的审查发送
      • 如果初始通知仍在发送中（例如正在等待快照或片段），更新会等它完成后再编辑它
      • 设为 false 则只在初始通知时已包含 GenAI 数据的情况下包含它
    • summary_idle_time（可选 - 默认：300）
      • 环境变量：FN_ALERTS__GENERAL__GENAI__SUMMARY_IDLE_TIME
      • 在一阵活动之后，当有这么多秒没有发送新通知时，向 Frigate 请求一份 GenAI 活动总结
      • 总结涵盖活动期间所有相机的全部事件
      • 只有当该时段内至少有一个审查被 GenAI 标记为威胁等级高于正常或有其他关注点时，才会发送总结；例行活动不会产生总结
      • 需要 Frigate 配置了 GenAI 提供商（在 Frigate 0.18+ 上，需要一个带 descriptions 角色的提供商）
      • 在 Frigate 0.18+ 上，总结端点要求能访问每个相机，因此 frigate 下配置的 Frigate 用户必须是 admin、viewer，或是覆盖所有相机的自定义角色
      • 设为 0 可禁用活动总结
    • schedules（可选）
      • 在固定的本地时间向 Frigate 请求一份 GenAI 总结，并作为通知发送
      • 每条计划每天最多运行一次；时间使用容器的本地时间（把容器的 TZ 设为与你的 Frigate 主机一致）
      • time（必填）- 本地时间，HH:MM 格式，例如 20:00
      • window（可选 - 默认：today）- 要总结的时间窗口：today（午夜到运行时刻）或 last_Nh（往前 N 小时，例如 last_11h 涵盖 20:00 到 07:00）
      • targets（可选）- 接收定时总结的渠道档案；如果为空，每个已启用的渠道都会收到
      • enabled（可选 - 默认：true）- 设为 false 可在不删除计划的情况下禁用它
      • 每条计划也可以从 Web UI 按需运行（状态页，“立即执行”）
Config File Snippet
alerts:
  general:
    title: Frigate Alert
    cooldown: 10
    camera_cooldown:
      doorbell: 30
    timeformat: Mon, 02 Jan 2006 15:04:05 MST
    nosnap:
    snap_bbox:
    snap_timestamp:
    snap_crop:
    snap_hires:
    max_snap_retry:
    notify_once:
    notify_detections:
    audio_only:
    genai:
      enabled: true
      update_notif: true
      summary_idle_time: 300
      schedules:
        - time: "20:00"
          window: today
        - time: "07:00"
          window: last_11h

路由

路由规则把每条通知收窄到选定的渠道档案，GenAI 升级规则则在审查后来被升级到更高威胁等级时发送一条全新的通知。两者都在 alerts.routing 下配置，并可从 Web UI 编辑（配置页，“路由规则”）。

  • rules（可选）
    • 路由规则列表，按顺序求值；每条匹配规则的目标会被合并
    • 每条规则有一个 name，以及可选的 cameras、labels、zones、sublabels 列表（列表内为“或”关系；空列表匹配一切），外加 min_threat（0 正常、1 可疑、2 危急；-1 匹配任何威胁等级，为默认）
    • 尚无 GenAI 数据的事件按威胁等级 0 计算
    • targets 是 {provider, index} 对的列表（index: -1 选中该渠道的全部档案）
    • 如果没有规则匹配，通知回退到之前的行为（所有已启用的渠道，仍受其过滤条件约束）
  • escalation（可选）
    • GenAI 数据可能在初始通知之后到达，而当时事件的威胁等级还是 0——因此“危急走所有渠道”的路由规则无法在初始通知时触发。升级正是来补上这个缺口的
    • 每条规则有一个 min_threat（默认 1，可疑）和 targets
    • 当某个已通知审查的 GenAI 更新达到 min_threat 时，会向规则目标发送一条全新通知，同时对最初通知的渠道做说明文字编辑
    • 每个（审查，规则）对最多触发一次；之后到达的更高威胁更新可以触发更高的规则
    • 升级通知绕过冷却，但计入 max_notifications_per_hour
Config File Snippet
alerts:
  routing:
    rules:
      - name: "Front door suspicious to Telegram"
        cameras:
          - front_door
        labels:
          - person
        min_threat: 1
        targets:
          - provider: telegram
            index: 0
      - name: "Critical events everywhere"
        min_threat: 2
        targets:
          - provider: telegram
            index: -1
          - provider: webhook
            index: 0
    escalation:
      - min_threat: 1
        targets:
          - provider: telegram
            index: -1

静默时段

定义一个静默时段，并在此期间抑制通知。

  • start（可选）
    • 环境变量：FN_ALERTS__QUIET__START
    • 静默时段开始的时间，24 小时制
    • 如果配置了 end，则此项必填
  • end（可选）
    • 环境变量：FN_ALERTS__QUIET__END
    • 静默时段结束的时间，24 小时制
    • 如果配置了 start，则此项必填
Config File Snippet
alerts:
  quiet:
    start: 08:00
    end: 17:00

区域

本配置部分可以控制是对所有区域都产生通知，还是只对特定区域。默认情况下，应用会对所有 Frigate 事件产生通知，无论事件是否包含区域信息。

A note about how this works

使用 MQTT 时，Frigate 会在检测开始时发送一个 new 事件。后续变化，例如被检测对象从一个区域移动到另一个区域，会触发 update 事件。这些 update 事件会包含对象当前所在区域的列表，以及对象在事件期间进入过的所有区域的列表。

为了减少产生的通知数量，本应用只会在被检测对象第一次进入某个区域时通知。

在 reviews 模式下，这在被跟踪对象的整个生命周期内都成立，即使它跨越多个 Frigate 审查：已经就某个区域通知过的对象，不会在之后的审查中就同一区域再次通知。对象通知过的区域会被记住，直到它有 1 小时没有在新区域上通知。审查在它至少有一个对象位于尚未通知过的区域时通知，且通知只涵盖那些对象；已经通知过的对象会被排除，而不是拖住整个审查。

例如，假设你的前院相机有 sidewalk、driveway 和 lawn 三个区域——但只允许 driveway 和 lawn 的通知。在一次事件中，某人最初在 sidewalk 被检测到，然后依次经过 driveway、lawn，又回到 driveway。这种情况下，你应该只收到两条通知。一条是此人第一次进入 driveway 区域时，一条是进入 lawn 区域时。

使用 Web API 事件查询时，我们只向 Frigate 查询一次事件。因此目前只会根据 Web API 查询新事件时检测到的区域发送一条通知。

  • unzoned（可选 - 默认：allow）
    • 环境变量：FN_ALERTS__ZONES__UNZONED
    • 控制对区域外事件的通知
    • 默认情况下，没有区域的事件会产生通知
    • 设为 drop 可阻止对没有区域的事件产生通知
  • allow（可选）
    • 环境变量：FN_ALERTS__ZONES__ALLOW
    • 指定一份允许通知的区域列表
    • 所有其他区域将被忽略
    • 如果 unzoned 设为 allow，没有区域信息的事件仍会发送通知
    • 如果通过环境变量配置，用分号分隔区域名称
  • block（可选）
    • 环境变量：FN_ALERTS__ZONES__BLOCK
    • 指定一份始终忽略的区域列表
    • 它优先于 allow 列表
    • 如果通过环境变量配置，用分号分隔区域名称
Config File Snippet
alerts:
  zones:
    unzoned: allow
    allow:
     - test_zone_01
    block:
     - test_zone_02

标签

与区域类似，通知也可以根据标签过滤。默认情况下，应用会产生通知，不论从 Frigate 收到什么标签。使用本配置部分，可以屏蔽某些标签发送通知——或者提供一份允许列表，只从指定标签产生通知。

  • min_score（可选 - 默认：0）
    • 环境变量：FN_ALERTS__LABELS__MIN_SCORE
    • 按最低标签分数过滤，基于 Frigate 的 top_score 值
    • 分数是对象识别的准确率百分比（0-100）
    • 例如，要过滤准确率低于 80% 的对象，设置 min_score: 80
    • 默认情况下，任何高于 0 的分数都会产生通知
  • 档案级 min_score（可选）
    • 每个渠道档案的过滤条件也可以带一个 min_score 映射（label: 0.0-1.0），这样不同标签可以在每个渠道有不同的最低分数——见通知档案与过滤
    • 只有当某个标签的每一次带分数检测都低于其最低值时，该标签的检测才会被丢弃；没有分数的检测永远不会被丢弃
  • allow（可选）
    • 环境变量：FN_ALERTS__LABELS__ALLOW
    • 指定一份允许通知的标签列表
    • 如果设置，所有其他标签将被忽略
    • 如果未设置，所有标签都会产生通知
    • 如果通过环境变量配置，用分号分隔标签名称
  • block（可选）
    • 环境变量：FN_ALERTS__LABELS__BLOCK
    • 指定一份始终忽略的标签列表
    • 它优先于 allow 列表
    • 如果通过环境变量配置，用分号分隔标签名称
Config File Snippet
alerts:
  labels:
    min_score: 80
    allow:
     - person
     - dog
    block:
     - bird

    • 环境变量：FN_ALERTS__SIGNAL__SERVER
    • 目标 signal-cli-rest-api 容器的完整 URL
    • 如果启用了这种通知方式，此项必填
  • account（必填）
    • 环境变量：FN_ALERTS__SIGNAL__ACCOUNT
    • 用于发送通知的 Signal 账号
    • 这是包含国家代码的完整电话号码（例如 +12223334444）
    • 如果启用了这种通知方式，此项必填
  • recipients（必填）
    • 环境变量：FN_ALERTS__SIGNAL__RECIPIENTS
    • 一个或多个接收通知的 Signal 接收者
    • 这是包含国家代码的完整电话号码（例如 +12223334444）
    • 如果启用了这种通知方式，此项必填
  • ignoressl（可选 - 默认：false）
    • 环境变量：FN_ALERTS__SIGNAL__IGNORESSL
    • 设为 true 可允许自签名证书
  • template（可选）
    • 环境变量：FN_ALERTS__SIGNAL__TEMPLATE
    • 可选地指定一个自定义通知模板
    • 模板语法的更多信息见通知模板

SMTP

  • enabled（可选 - 默认：false）
    • 环境变量：FN_ALERTS__SMTP__ENABLED
    • 设为 true 通过 SMTP 启用通知
  • server（必填）
    • 环境变量：FN_ALERTS__SMTP__SERVER
    • 目标 SMTP 服务器的 IP 或主机名
    • 如果启用了这种通知方式，此项必填
  • port（必填）
    • 环境变量：FN_ALERTS__SMTP__PORT
    • 目标 SMTP 服务器的端口
    • 如果启用了这种通知方式，此项必填
  • tls（可选 - 默认：false）
    • 环境变量：FN_ALERTS__SMTP__TLS
    • 如果 SMTP 需要 TLS，设为 true
  • authtype（可选 = 默认：plain）
    • 环境变量：FN__ALERTS__SMTP__AUTHTYPE
    • 设置 SMTP 认证类型
    • 有效选项：plain, plain-noenc, login, login-noenc, noauth, cram-md5, xoauth2, scram-sha-1, scram-sha-1-plus, scram-sha-256, scram-sha-256-plus, autodiscover
  • user（可选）
    • 环境变量：FN_ALERTS__SMTP__USER
    • 添加用于鉴权的 SMTP 用户名
    • 如果用户名和密码都未设置，则禁用鉴权
  • password（可选）
    • 环境变量：FN_ALERTS__SMTP__PASSWORD
    • SMTP 用户的密码
    • 如果设置了 user，则此项必填
  • from（可选）
    • 环境变量：FN_ALERTS__SMTP__FROM
    • 设置外发邮件的发件人地址
    • 如果留空但配置了鉴权，则使用 user
  • recipient（必填）
    • 环境变量：FN_ALERTS__SMTP__RECIPIENT
    • 逗号分隔的邮件接收者列表
    • 如果启用了这种通知方式，此项必填
  • thread（可选 - 默认：day）
    • 环境变量：FN_ALERTS__SMTP__THREAD
    • 控制 SMTP 通知如何串联成会话（如果你的邮件客户端支持）
    • 有效的串联选项为 day 或 camera
    • 注意： 按 camera 串联的会话仍会每天滚动一次
    • 注意： 如果你修改了默认的 frigate-notify-plus 消息标题，可能会在通知之间主题变化时破坏串联
  • template（可选）
    • 环境变量：FN_ALERTS__SMTP__TEMPLATE
    • 可选地指定一个自定义通知模板
    • 模板语法的更多信息见通知模板
  • title（可选）
    • 环境变量：FN_ALERTS__SMTP__TITLE
    • 可选地为该通知渠道覆盖全局消息标题
    • 标题值可以使用模板变量
  • ignoressl（可选 - 默认：false）
    • 环境变量：FN_ALERTS__SMTP__IGNORESSL
    • 设为 true 可允许自签名证书
  • msguuid（可选 - 默认：false）
    • 环境变量：FN_ALERTS__SMTP__MSGUUID
    • 设为 true 可从 uuid 生成 message-id

Telegram

Note

如果你为 Frigate 链接使用 URL 内嵌凭据，Telegram 通知存在一个问题，例如：https://user:pass@frigate.domain.tld

Telegram 似乎会错误地处理这类 URL，这会导致相机和片段链接在 Telegram 中无法点击。

要使用 Telegram 发送通知，需要一个 bot 令牌和一个 chat ID。

要获取 bot 令牌，按照这篇文档给 @BotFather 发消息。

拿到 bot 令牌后，确保先给你的 bot 发起一次聊天消息。然后访问以下 URL：

  • https://api.telegram.org/bot<BOT_TOKEN>/getUpdates
  • 把 <BOT_TOKEN> 替换为 @BotFather 提供的 API 令牌。

在响应中找到你发给 bot 的消息，然后取 message > chat > id 下的 ID。下面的示例响应中，999999999 就是我们需要保存的 ID：

{
  "update_id": 1234567,
  "message": {
    "chat": {
      "id": 999999999,
      "first_name": "Test User",
      "username": "test-username1234",
      "type": "private"
    }
  }
}
  • enabled（可选 - 默认：false）
    • 环境变量：FN_ALERTS__TELEGRAM__ENABLED
    • 设为 true 通过 Telegram 启用通知
  • chatid（必填）
    • 环境变量：FN_ALERTS__TELEGRAM__CHATID
    • 通知接收者的 Chat ID
    • 如果启用了这种通知方式，此项必填
  • token（必填）
    • 环境变量：FN_ALERTS__TELEGRAM__TOKEN
    • 从 @BotFather 生成的 Bot 令牌
    • 如果启用了这种通知方式，此项必填
  • send_clip（可选 - 默认：false）
    • 环境变量：FN_ALERTS__TELEGRAM__SEND_CLIP
    • 可选地发送事件视频片段而不是快照图片
    • 注意：片段可能需要一小段时间才能可用。用 max_snap_retry 控制 frigate-notify-plus 等待片段可用的时长
  • send_clip_after_snapshot（可选 - 默认：false）
    • 环境变量：FN_ALERTS__TELEGRAM__SEND_CLIP_AFTER_SNAPSHOT
    • 可选地先立即发送快照图片，然后在事件视频片段可用时把同一条消息替换为片段
    • 与 send_clip（发送任何东西之前先等待片段）不同，这个选项会立即送达快照，并在原地把它升级为视频——因此总能发出一条快速通知，而如果片段始终不可用或超过 clip_max_size，快照会被保留
    • 当两者都启用时，优先于 send_clip
    • 注意：片段可能需要一小段时间才能可用。用 max_snap_retry 控制 frigate-notify-plus 等待片段可用的时长
  • clip_max_size（可选 - 默认：50）
    • 环境变量：FN_ALERTS__TELEGRAM__CLIP_MAX_SIZE
    • 通过 send_clip_after_snapshot 替换快照时将上传的片段最大大小，单位为 MB。更大的片段会被跳过，快照会被保留
    • Telegram 云端 Bot API 把 bot 上传上限设为 50 MB。如果你运行自建的 Local Bot API 服务器，可以把这个值提高到 2000
  • clip_transcode（可选 - 默认：false）
    • 环境变量：FN_ALERTS__TELEGRAM__CLIP_TRANSCODE
    • 可选地在上传前把片段重新编码为更小的 H.264/AAC 视频，使其下载更轻量。同时适用于 send_clip 和 send_clip_after_snapshot
    • 需要 ffmpeg，它包含在 Docker 镜像中。如果直接运行二进制文件，必须安装 ffmpeg
    • 启用时，clip_max_size 作用于转码后的片段
    • 如果转码失败或超过 clip_transcode_timeout，则改为发送或保留快照
    • 如果转码后的片段并不比原始片段小，则发送原始片段
    • 同一时间只转码一个片段。每个片段都会记录转码前后的大小和所用时间
  • clip_transcode_height（可选 - 默认：720）
    • 环境变量：FN_ALERTS__TELEGRAM__CLIP_TRANSCODE_HEIGHT
    • 转码后片段的最大高度，单位为像素。宽度按宽高比跟随，更小的片段不会被放大
  • clip_transcode_bitrate（可选 - 默认：1000）
    • 环境变量：FN_ALERTS__TELEGRAM__CLIP_TRANSCODE_BITRATE
    • 转码后片段的最大视频码率，单位为 kbit/s。音频额外占 64 kbit/s
    • 默认值下，10 秒片段大约产生 1.3 MB，一分钟大约 8 MB
  • clip_transcode_timeout（可选 - 默认：120）
    • 环境变量：FN_ALERTS__TELEGRAM__CLIP_TRANSCODE_TIMEOUT
    • 等待 ffmpeg 转码一个片段的最长秒数
  • clip_transcode_vaapi_device（可选）
    • 环境变量：FN_ALERTS__TELEGRAM__CLIP_TRANSCODE_VAAPI_DEVICE
    • 可选地通过指定渲染设备（例如 /dev/dri/renderD128）使用 GPU 经 VAAPI 转码。这比默认的软件编码器更快、CPU 占用低得多，但相同码率下画质略低
    • 设备必须传入容器。Docker 镜像包含 Intel VA 驱动（仅 x86_64）
    • 如果 GPU 转码因任何原因失败，片段会改用软件转码
  • message_thread_id（可选）
    • 环境变量：FN_ALERTS__TELEGRAM__MESSAGE_THREAD_ID
    • 可选地按 ID 把通知发送到某个消息话题
  • template（可选）
    • 环境变量：FN_ALERTS__TELEGRAM__TEMPLATE
    • 可选地指定一个自定义通知模板
    • 模板语法的更多信息见通知模板
Config File Snippet
alerts:  
  telegram:
    enabled: true
    chatid: 123456789
    message_thread_id: 100
    send_clip:
    send_clip_after_snapshot:
    clip_max_size: 50
    clip_transcode:
    clip_transcode_height: 720
    clip_transcode_bitrate: 1000
    clip_transcode_timeout: 120
    clip_transcode_vaapi_device:
    token: 987654321:ABCDEFGHIJKLMNOP
    template:

Webhook

Note

Webhook 通知只包含 JSON，不包含事件的图片。

Default webhook message
{
    "time": "",
    "id": "",
    "camera": "",
    "label": "",
    "score": "",
    "current_zones": "",
    "entered_zones": "",
    "has_clip": "",
    "has_snapshot": "",
    "links": {
         "camera": "",
         "clip": "",
         "snapshot": ""
    },
    "genai": {
         "title": "",
         "summary": "",
         "description": "",
         "threat_level": "",
         "confidence": "",
         "concerns": "",
         "observations": []
    }
}

Note

genai 字段只有当 Frigate 有 GenAI 数据可用时才包含。如果 Frigate 没有配置 GenAI，或事件没有 GenAI 数据，此字段会被省略。

  • enabled（可选 - 默认：false）
    • 环境变量：FN_ALERTS__WEBHOOK__ENABLED
    • 设为 true 通过 webhook 启用通知
  • server（必填）
    • 环境变量：FN_ALERTS__WEBHOOK__SERVER
    • 目标 webhook 服务器的完整 URL
    • 如果启用了这种通知方式，此项必填
  • ignoressl（可选 - 默认：false）
    • 环境变量：FN_ALERTS__WEBHOOK__IGNORESSL
    • 设为 true 可允许自签名证书
  • method（可选 - 默认：POST）
    • 环境变量：FN_ALERTS__WEBHOOK__METHOD
    • 设置 webhook 通知的 HTTP 方法
    • 支持 GET 和 POST
  • params（可选）
    • 环境变量：FN_ALERTS__WEBHOOK__PARAMS
    • 设置将附加到 URL 的可选 HTTP 参数
    • 参数可以使用模板变量
    • 格式：param: value
    • 示例：token: abcd1234
  • headers（可选）
    • 环境变量：FN_ALERTS__WEBHOOK__HEADERS
    • 向 webhook 接收端发送额外的 HTTP 请求头
    • 请求头的值可以使用模板变量
    • 请求头格式：Header: Value
    • 示例：Authorization: Basic abcd1234
  • template（可选）
    • 环境变量：FN_ALERTS__WEBHOOK__TEMPLATE
    • 可选地指定一个自定义通知模板
    • 只在 method 为 POST 时适用
    • 模板语法的更多信息见通知模板
    • 注意：Webhook 模板必须是有效的 JSON
Config File Snippet
  webhook:
    enabled: false
    server: 
    ignoressl:
    method:
    params:
    headers:
    template:

监控

如果启用，本应用会定期向 HealthChecks 或 Uptime Kuma 等工具签到，用于健康 / 状态监控。

  • enabled（可选 - 默认：false）
    • 环境变量：FN_MONITOR__ENABLED
    • 设为 true 启用健康检查
  • url（必填）
    • 环境变量：FN_MONITOR__URL
    • 健康检查服务的 URL 路径
    • 如果启用了监控，此项必填
  • interval（必填 - 默认：60）
    • 环境变量：FN_MONITOR__INTERVAL
    • 签到事件的频率
    • 如果启用了监控，此项必填
  • ignoressl（可选 - 默认：false）
    • 环境变量：FN_MONITOR__IGNORESSL
    • 设为 true 可允许自签名证书
Config File Snippet
monitor:
  enabled: false
  url: 
  interval: 
  ignoressl:
